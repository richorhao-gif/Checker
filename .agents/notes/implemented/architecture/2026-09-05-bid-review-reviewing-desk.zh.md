# Agent Note: The bid review's reviewing desk over a shadowed view cell

Status: implemented

[English](2026-09-05-bid-review-reviewing-desk.md) | 中文

> 遮蔽注册、派生姿态、替身纸面与意见书自己的读取都仍然有效。印章先搜「不符合」再搜「符合」的全文扫描被[判定声明行](../bug-fix/2026-09-06-bid-verdict-declaration-line.md)取代：它只读意见书头部的一行 `判定：`，并把「待核验」加为第三个结论。

## Problem

固定问题标书审核（[intake Agent Note](2026-09-04-bid-review-fixed-prompt-surface.md)）提交一条 prompt，然后把屏幕交给普通转录。对该部署而言转录是错误的界面：它把工具头、流式正文与推理交织成一段需要审核人自行解读的滚动内容，而审核人只问两件事——审核还在跑吗，结论是什么。该部署也没有第二个页面可以放报告，因为一个会话只受理一份文件与一个问题。

进度页可以回答这两件事，但前提是它所说的每个阶段都是真的。Session 日志中没有任何东西区分「核对供应商资格」与「提取评分准则」：日志承载回合、工具调用、流式状态、待处理交互与收尾的 assistant 文本，没有标书业务的词汇。任何显示「资格核对 60%」的页面都在编造一个无人执行的测量。

## Decision

Client 包贡献第二个遮蔽条目——审卷台，并由 `ui-conversation` 中的一条共享规则让这次遮蔽可读。`ReviewDesk` 通过 `ctx.slots.inject` 以 `priority: -1` 注册进 `conversation.view` list 槽的 `chat` 格，并携带自己的 `label` thunk，因此一次已提交的审核呈现为一张正在审阅的纸，而不是一份转录；移除本插件即恢复对话视图。

审卷台画出的一切都是派生的，从不被持有。[`src/client/desk.ts`](../../../../packages/client/ui-bid-review/src/client/desk.ts) 通过纯函数 `deriveDesk` 把十个会话 snapshot 字段折叠成一个 `DeskView`，组件只渲染该结果，因此刷新、切换 Session 与 Host 自己对回合的判断都不可能和页面不一致。审卷台的本地状态只有呈现层：计时器背后的时钟读数、翻页、复制确认，以及两次 Remote 读取。

没有任何 stage 从 prompt 或 assistant 文本里读出，也没有任何 stage 是编造的。标书业务的阶段必须先发布为 Session 事件；在这样的事件存在之前，审卷台的词汇就是循环自己的词汇。

## Shadowing one cell of a list slot

`conversation.view` 是 `{ kind: 'list', scope: 'session' }` 槽，因此其条目按格冲突而非整体冲突：同一 `id` 上的两个条目互相竞争，优先级最低的存活条目渲染该格，其余留在 ledger 上。这与 single-kind 槽对其唯一条目所用的选举规则相同，也正因如此 `priority: -1` 能在不修改声明包的条件下遮蔽对话渲染器。

投影页签栏需要 `ui-conversation` 中一处改动：`viewTabs()` 遍历 `slots.entriesOfSlot('conversation.view')`，即注册表选举出的条目，而不是原始 ledger，因此遮蔽条目替换页签，而不是在它旁边多出一个重影。原始 ledger 仍是检查面，且该格保留自己的 `id`，所以任何按 id 寻址对话视图的代码与旁边的 `trajectory` 格都不变。审卷台渲染期间，`ChatStoreState.view` 仍持有 `'chat'`。

审卷台没有接管 `conversation.session`：后者持有 blank 阶段的返回、持久化的草稿镜像与已释放的 Session 图片，且其共享 store 句柄不能被挂载两次。这些框架职责留在其 owner 处，审卷台与其他视图条目一样接收组合出的 `useSession` 座位。

遮蔽 chat 格也遮蔽了转录的「加载更早」按钮——那是把持久化历史拉进一个重开 Session 的对话窗口的唯一产品触发器。没有它，一次封卷后才打开的审核会把审卷台困在一个从空白开始的窗口上，对着它看不见的日志显示等待姿态。因此审卷台通过 inject 接收 `loadOlder` 动词并自行翻页，直到提交的 prompt 进入窗口；并在提交已存在、某页仍在加载、没有更早内容可加载、或 Session 已消失时停止。

## What the desk derives

`deriveDesk` 对各姿态排序，使存活的等待压过进行中的回合、进行中的回合压过已记录的错误，而只有在没有别的事未完成时，已结束的回合才封卷：Host 已移除 Session 时 `ended`，日志为空且 composer phase 为空时 `hidden`，第一个待处理审批或反问时 `paused`，回合运行时 `working`，有持久失败文案、或某个回合的流式 partial 冻结为 `interrupted` 时 `failed`——那是刷新后唯一能存活、用以区分被中止的审核与已完成的审核的事实，因此写到一半被切断的回合永不封卷——然后按窗口内最高回合是否带结束时间取 `waiting` 或 `sealed`。`working` 的审卷台还说出该回合在做什么——正在运行的工具压过流式正文，正文压过静默——因为 snapshot 不区分更细的状态，状态栏只说它确切知道的最少内容。

画出的四个值是日志自己的。页边标记每个对应一次已结算的工具调用，超过十二个后均匀抽样，因此每个标记仍指向一个真实的序号。计时器对进行中的回合按一秒一次的时钟给出其自身跨度，回合结束后给出最后一个回合的跨度。暂停注记在提问者给出原因时携带该原因，否则回退到说出工具名或说明这是一个反问。印章与意见书正文都是模型的收尾文字。

纸面本身是替身，并被如此记录在案。它的盲行是固定文案，着色高度跟随已结算调用数，因此审卷台显示阅读在推进，却不宣称一个文件内部被测量的位置——没有任何代码检查那个文件。审卷台也只指出等待在哪：回答它的审批或反问面板仍在本包不遮蔽的 `conversation.composer` chain 上。

## The sealed turn and the opinion sheet

封卷的审卷台在批注页上落印，保持 1.8 秒，然后翻到意见书；`prefers-reduced-motion` 下立即翻面；两面都可以手动翻回。意见书页眉取 `getLimits().companyName`——第四个必填 Host Config 字段——部署未命名公司时回退到本包自己的文案，而交付的 Web bundle 值就是空字符串。依据行说明被审文件与共享记录的保存时间，或直言记录读不到、为空、从未保存过，而不假装有依据。红头编号是 Session id 去掉 store 的 `session-` 铸造前缀、再截取八个字符，因此按计数器铸造的 id 读作它的计数器，持久 id 读作一个稳定前缀，而不是单独一个铸造词。`verdictOf` 从收尾文本里读出结论：出现任何「不符合」判为不通过，否则出现「符合」判为通过，两者都没说的报告让印章不落结论，而不是猜一个。

页眉与依据都是部署自己的文字，因此每次封卷审核通过注入的 `readLimits` 与 `readQualifications` 各读一次；在审卷台消失之后才返回的读取被丢弃，而不是画到已卸载的页面上。复制意见书走 `ui-primitives` 共享的 `writeClipboard`，它持有异步 API 与 `execCommand` 两条回退并返回宿主是否接受了写入，因此浏览器拒绝时按钮不宣称已复制；保存走 `downloadText`，落成一个以被审文件命名的 Markdown 文件，顺序与意见书自身的阅读顺序一致。

## Alternatives considered

**遮蔽 `conversation.session` 而不是一个视图格。** 否决：`SlotCore.register` 在注册方重复声明某个槽的 `children` 时抛错，共享的 `chatStore` 句柄不能被挂载两次，而该 owner 持有 blank 阶段返回、草稿镜像与 `releaseSessionImages`。视图 list 中的一个格给出同样的可见结果，并把这些职责留在它们被声明的地方。

**在 `viewTabs()` 内部过滤重复 id。** 否决：`entriesOfSlot` 是注册表自己的选举规则，消费方重新实现「先到者优先」会把它分叉。读取被选举的条目，使「哪个条目渲染某个格、哪个页签命名它」只有一个权威。

**在 prompt 中标记标书阶段再解析回来。** 否决：那会把一个客户端自有的协议塞进模型可见的用户消息，而回复仍只是审卷台要去猜的散文。部署方要求进度只来自真实事件。

**为标书阶段发布新的 Session 事件。** 本次改动否决。这是通往标书业务进度的诚实路径，并且仍然敞开，但它需要有人拥有 Agent 当前并不发出的阶段语义，而一个 `SessionEventMap` 成员对每个构建都是读取必需的。审卷台基于循环已经记录的事件交付。

**显示一个从文件读出的百分比。** 否决：没有任何东西测量文件内部的位置，因此任何百分比都是编造的。替身的色调是已结算调用的计数，模块文档写明它不是一个测量值。

**保留转录并在其上方加一个进度头。** 否决：两个渲染器覆盖同一批节点，会各自宣称对同一批事实拥有权威，而部署方要的是每次审核一个界面。需要节点的人仍有 trajectory 视图。

**把审卷台的姿态存在组件状态里。** 否决：派生状态能在刷新后存活并与 Host 一致，而组件标记会在审核中途刷新后漂移，并可能与 Host 已经结束的回合相矛盾。

**自己实现意见书的剪贴板写入。** 否决，改用共享的 `writeClipboard`：它已经携带回退，以及「被拒绝的写入不得报告为已复制」这条规则。

## Testing

`desk.ts` 以表格覆盖每个姿态（包括判为 `failed` 而非封卷的 interrupted 回合）、超过十二个后的标记抽样、结论／依据／页眉决策、编号派生、进行中与已结束两种回合下的时间跨度，以及导出文本与文件名。`ReviewDesk` 在 jsdom 中渲染每个姿态，并用 fake timers 锁定计时行为：一秒一次的时钟、1.8 秒的落印保持与 `prefers-reduced-motion` 下的立即翻页、两个方向的手动翻页、通过交付的英文词典验证的长文案缩印、卸载后被丢弃的页眉读取、被宿主拒绝的复制、下载，以及审卷台自行翻页直到提交进入窗口。

`ui-conversation` 的 inject 测试经由真实的 `apply()` 断言选举出的页签：`chat` 格上一个 `priority: -1` 条目替换页签文案，两条注册都留在原始 ledger 上，处置遮蔽后恢复 owner 的页签。两个包在仓库门禁下都报告完整的按文件覆盖率。

这里没有任何模型可见内容，也没有 `SessionEventMap` 成员变化，因此没有 keyless snapshot fixture 变动：审卷台读取循环已经记录的事件，不添加任何到达模型请求的输入。组装后的 Web 界面在浏览器中验证。

## Consequences

一次已提交的审核只有一个产品界面，而审卷台渲染期间对话转录不被挂载。Session 的节点仍可在 `trajectory` 视图中阅读，该格保留自己的 id，因此持久化的视图选择与任何按 id 寻址对话视图的代码都不受影响。

进度是 agent 循环的，不是标书业务的。想要标书业务阶段的部署必须先把它们发布为 Session 事件；审卷台不从 prompt 或 assistant 文本里读阶段，因此它的词汇与日志的词汇一样粗。

意见书是模型的收尾文本，因此以工具调用收尾的审核渲染「没有留下结论文本」的文案，而两个结论词都没出现的报告带着未落结论的印章。二者都不被纠正，因为编一个模型没有给出的结论会让意见书说谎。

页眉依赖 Host Config 命名一家公司。交付的 Web bundle 设为空字符串，因此在部署方声明其公司之前，意见书用自己的文案作页眉；`companyName` 是必填而非带默认值，因为 Cordis 在构造函数之前就应用 Config 默认值，那会让构造函数一侧的回退成为不可达分支。

`ui-conversation` 中的一条页签投影规则现在是共享的：任何遮蔽某个视图格的包都替换该格的页签，而不是多出一个。这是遮蔽 list 槽的预期语义，也是本界面唯一改动的既有包行为。
